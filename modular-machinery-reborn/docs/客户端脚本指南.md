# 客户端脚本指南（0.118.3）

需要 Minecraft 1.20.1 / Forge、Reborn 和 KubeJS 6。脚本放在 **`kubejs/client_scripts/`**；修改后执行 **`/kubejs reload client_scripts`**。客户端资源包修改后刷新资源。数据包和服务端脚本仍使用 `/reload`。

GUI 信息、模型选择和动画事件在客户端执行。模型／动画还需要 GeckoLib；只追加 GUI 信息时可以不安装 GeckoLib。当前通信协议为 **7**，客户端和服务端应保持一致。

## GUI 信息行

```js
MachineClientEvents.guiRender('my_pack:press', event => {
  const c = event.controller
  event.addInfo('进度：' + c.progress + '/' + c.duration)
  event.addInfo(c.working ? '设备运行中' : '设备空闲')
})
```

普通控制器与工厂控制器都支持。信息行沿用界面的换行和可见区域限制；较长内容可能被裁切。这个接口对应控制器的信息文字扩展，不提供任意画布或自定义交互控件。

| 接口 | 含义 |
|---|---|
| `addInfo(...strings)` | 追加明文信息行 |
| `addTranslatedInfo(key, ...stringArgs)` | 追加翻译文本和替换参数 |
| `extraInfo` | 读取当前附加信息的字符串数组 |
| `extraInfo = ['a', 'b']` | 继续追加信息，保留已有行 |

省略机器 ID 可以监听所有机器，例如 `MachineClientEvents.guiRender(event => {...})`。模型和动画事件也支持这两种订阅形式。分发遵循 KubeJS：先匹配机器 ID 的监听器，再全局监听器。回调可能每帧多次执行，应只计算显示内容。

## 客户端控制器视图

所有事件都有 `event.controller`，并提供 `event.machine`、`event.pos` 和 `event.world`。

| 只读属性 | 含义 |
|---|---|
| `machine`、`pos`、`world`、`blockState` | 当前机器 ID、坐标、客户端世界和方块状态 |
| `formed`、`working`、`factory` | 结构、运行与工厂状态 |
| `progress`、`duration`、`parallelism` | 客户端收到的进度、时长和并行数 |
| `activeRecipe`、`ownerUUID` | 当前配方及所有者，可能为空 |
| `statusMessage` | 已同步的脚本状态文字 |
| `customData` | 客户端已同步自定义 NBT 的副本 |

视图没有修改进度、线程或服务端修改器的方法。`customData.putInt(...)` 只改返回副本，不会写回控制器。数据反映最近一次方块实体同步，不保证每个渲染帧都与服务端实时一致。服务端逻辑继续使用 [高级脚本指南](高级脚本指南.md) 中的接口。

## 具名模型与模型选择

客户端脚本顶层可注册模型：

```js
MachineClientModels.register('my_pack:working', {
  model: 'my_pack:geo/press.geo.json',
  texture: 'my_pack:textures/press_working.png',
  animation: 'my_pack:animations/press.animation.json',
  idle: 'idle',
  working: 'working'
})

MachineClientEvents.modelGet('my_pack:press', event => {
  if (event.controller.working) event.modelName = 'my_pack:working'
})
```

资源包中的路径分别是 `assets/my_pack/geo/press.geo.json`、`assets/my_pack/textures/press_working.png` 和 `assets/my_pack/animations/press.animation.json`。`model` 和 `texture` 必填；`animation` 可省略，但声明 `idle`／`working` 动画名时必须提供动画文件。

资源解析复用已有 `geo-model` 规则：建议显式填写自己的命名空间；没有命名空间或填写 `minecraft:` 时仍按既有规则改写为 `modularmachinery:`。示例若需要原版贴图，应先放到自己的资源包路径下；也可引用本模组已有的 `modular_machinery_reborn:` 贴图。

`event.modelName` 为空时使用机器定义中的模型；具名模型未注册时回退定义。也可以直接写 `event.setModel({model: ..., texture: ..., animation: ...})`，对象字段与上表相同。直接模型与具名选择按最后一次写入决定。

`MachineClientModels.contains(name)` 查询，`remove(name)` 删除，`names` 返回名称列表。同名注册覆盖旧定义。客户端脚本重载会先清理这张表，再执行当前文件，已删除的定义不会残留；服务端重载不清理客户端模型表。

一帧中模型、贴图和动画文件使用同一份选择结果。模型切换时重置动画；资源刷新会重建动画缓存并保留具名模型注册。渲染资源出错时记录日志、停用该模型并尝试机器定义中的模型，直到下一次脚本／资源重载后重试。

## 动画控制

```js
MachineClientEvents.modelAnimation('my_pack:press', event => {
  event.transitionLengthTicks = 5
  event.animationSpeed = 1
  if (event.controller.working) {
    event.setAnimation('working', true)
  } else {
    event.setAnimation('idle', true)
  }
})
```

事件在已成型且有动画资源的模型上触发。没有脚本时，仍按机器定义的 `idle`／`working` 循环播放。事件初始序列包含当前默认动画；`setAnimation()` 替换序列，`addAnimation()` 在后面追加。

| 可写接口 | 含义 |
|---|---|
| `setAnimation(name, loop)` | 清除原序列并添加一个动画；省略 loop 时为单次播放 |
| `addAnimation(name, loop)` | 按顺序追加；省略 loop 时为单次播放 |
| `clearAnimations()` | 清空序列，使播放停止 |
| `playState` | 0 继续，1 停止 |
| `transitionLengthTicks` | 非负有限值，四舍五入为 GeckoLib 使用的整数 tick |
| `animationSpeed` | 非负有限倍率；0 暂停推进 |

动画名来自当前选中的动画文件。可先单次播放启动动画，再追加循环阶段：`event.setAnimation('start', false); event.addAnimation('working', true)`。序列不变时不会因每帧重新声明而从头播放；切换模型或重载会重置缓存。

可读属性包括 `currentModelName`、`currentAnimationName`、`animationTick`、`animationState`、`limbSwing`、`limbSwingAmount`、`partialTick`、`moving` 和当前 `animations`。`currentAnimationName` 可能为空；`animationState` 的 0／1／2 分别表示运行／过渡／停止或暂停。默认模型的 `currentModelName` 为模型资源路径，具名模型则为注册名。

## 错误与验收范围

脚本异常由 KubeJS 报告：GUI 当前批追加行不提交；模型选择恢复默认；动画恢复初始序列与参数。未知具名模型和资源渲染失败也有日志与回退路径。

这些接口已通过生产事件、实际 Rhino 注册／过滤／回调、GeckoLib 序列与参数传递的离线检查；未验收真实 GUI 和 OpenGL 动画画面。0.114.0 起，机器成型且自定义模型成功渲染后，会隐藏原控制器模型；开启 `hide-components-when-formed`／`.hideComponentsWhenFormed(true)` 时还会隐藏实际结构组件。模型失效时恢复方块显示，详见 [世界模型隐藏](世界模型隐藏.md)。
