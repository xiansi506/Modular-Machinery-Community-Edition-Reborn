# 0.118.5 魔法配方崩溃修复 / Magic recipe crash fix

## 报告与根因

用户报告为 2026-10-27 17:56:27 的 Ticking block entity，实际加载 0.118.4 / Forge 47.4.23；test1 控制器在复制配方时触发 readerIndex: 95, writerIndex: 82。安装包 SHA-256 与此前 0.118.4 归档一致。

统一 MachineRequirementParser 先读类型与 IOType，再交给类型读取正文。MagicRequirements.Handler.write 漏写 IOType，把 amount 的 double 高位当成 UTF 字符串长度。使用用户配方原样的 aura 需求（800、naturesaura:overworld）可离线复现完全一致的 82／95 越界。此缺陷同时影响魔力、灵气、LP 与意志，复制配方和整条配方网络同步共用这条路径。

## 修复与升级

魔法 writer 补写方向前缀，明确 RequirementType 的写入契约。正文中的金额、变体、上下限、逐 tick 标志以及公共 selector-tag、parallelize-unaffected、脚本参数均保持。此前 0.118.4 的修复全部保留。

**版本 0.118.5，协议 8。客户端与服务端必须同时更新，不能混用协议 7 或更早版本。** 配方 JSON 和存档格式不变，无需为此修改配方或删除控制器。

## 验证与测试补缺

新增 35 项专项由红转绿，本轮相关回归 3001 项，总计 3036 项零失败，生产 build/reobf 和资源检查通过。

- 对照旧 writer 的隔离复跑为 0／35，新实现为 35／0；原报告 aura 字段从 82 字节变成 88 字节，统一读取后无剩余或错位。旧 writer 副本仅放在审计目录，不打入 JAR。
- 覆盖四资源 × 双向 × 一次性／逐 tick、五种意志、分数与整数边界、标签／脚本参数、多个需求连续读写与尾部哨兵、真实 MachineSerializer 整条配方往返、executionCopy，以及普通／核心工厂中灵气＋水的两批连续结算。环境资源由内存端口提供，未代替真实世界资源验收。
- 旧魔法套件的四项“包往返”曾直接调用 writer 与 readBody，绕过共同读取器，导致漏检；本轮测试副本改走共同读写入口并检查完全消费，52 项保持通过。原测试与日志保留。
- 主套件 2669、真实魔法 API 23、示例 6、依赖隔离 89、上一轮专项 43、时序／AE2 33、预览／JEI 29、高级脚本 57 项亦通过。上一轮 43 项中自带 2000 组整数对照，不重复计入总数。
- 生产构建通过；203 JSON、中英各 424 键、协议 8／SRG／可选 API 隔离检查通过。

本轮未启动游戏、未部署、未修改世界或用户脚本、未提交／推送；修复后仍需实机复验。原错误报告是旧包崩溃证据，不是新包验收。

## English

Magic requirement writers omitted the IO prefix consumed by the common reader. The reported 800-Aura requirement reproduces the exact 95/82 buffer-boundary failure. The writer now includes the prefix, preserving all remaining fields. This repairs execution copies and recipe synchronization for mana, Aura, Life Essence and Demon Will.

Version 0.118.5 uses protocol **8**: update both clients and servers. JSON and save formats are unchanged. All 35 new regression checks fail with the old writer and pass with the fix; 3036 relevant checks passed in this patch. Previous direct-body tests were corrected to exercise full common framing. No game launch, deployment, commit or push was performed; repaired gameplay remains unverified.
