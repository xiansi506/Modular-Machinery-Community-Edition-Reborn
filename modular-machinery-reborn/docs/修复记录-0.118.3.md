# JEI 材料表轮换回退修复（0.118.3）

0.118.2 的结构预览材料槽在停留一段时间后，会全部显示为控制器，或一起轮换为同一种候选物品。用户截图中的实例确认为 0.118.2；本轮未更换或启动该实例。

根因是 JEI 的原生生命周期：`RecipeLayout.tick()` 中的材料轮换计时器每 20 tick 推进一次，清除槽位的显示覆盖，并调用分类的 `onDisplayedIngredientsUpdate`。0.118.2 只比较面板自己的缓存，误以为材料和位置没有变化，从而跳过恢复。所有槽位的隐藏索引候选相同，清除覆盖后便会一起显示焦点物品或同一个候选。

0.118.3 在 JEI 的显示材料更新回调中立即同步该布局的材料，同时比较槽位当前真正显示的物品。即使自己的缓存未变，只要 JEI 清除了覆盖，也会恢复正确的种类和数量。保持原有查询索引、动态结构、选中候选和独立历史布局机制。

新增六项回归在 0.118.2 上全部失败，在修复后全部通过。检查直接使用真实 JEI `RecipeLayout` 构造器、`tick()`、`CycleTicker` 和 `RecipeSlot`，覆盖初始化、焦点控制器、连续轮换、动态段归零／增减、选中方块与替代项，以及两个历史布局。运行所需的键位和 runtime 服务使用测试替身；没有运行真实 OpenGL 绘制。

此前的离线槽位检查没有驱动 JEI 的定时清除路径，因此未能发现这一回归。本轮补充真实布局生命周期，而非只反复调用同步方法。

协议仍为 **7**。生产包、验证数量及 SHA-256 见 [交接 §零](交接-2026-10-23.md)。本轮没有部署、暂存、提交或推送，修复后的游戏画面仍待实机确认。

## English

In 0.118.2, JEI could replace every material icon with the focused controller or cycle all slots through the same ingredient. JEI clears display overrides when its native ingredient timer advances. The preview's unchanged local cache then incorrectly skipped restoring the actual material stacks.

0.118.3 restores slots in `onDisplayedIngredientsUpdate` and also checks each slot's actual displayed stack before skipping synchronization. Six new regressions fail on 0.118.2 and pass after the fix. They execute the real JEI layout constructor and tick/cycler lifecycle, including focused controllers, repeated cycles, dynamic counts, selected alternatives and separate history layouts.

Runtime/key services use fixtures; no OpenGL drawing or repaired gameplay acceptance was performed. Protocol 7 and earlier functionality are retained. No game deployment or Git staging, commit, push or publication occurred.
