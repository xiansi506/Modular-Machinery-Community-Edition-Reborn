## 0. 先纠正一个前提：旧版是一个 jar，不是「本体 + 一堆 addon」

旧版快照里混着四个源码根，但**它们被编进同一个 jar**，而且**基座自己注册了它们的方块**：

| 包 | 文件 | 是什么 | 是否随旧版一起发布 |
|---|---|---|---|
| `hellfirepvp.modularmachinery` | 310 | MMCE 本体 | ✅ 是 |
| `github.kasuminova.mmce` | 219 | Kasu 增补（AE2 总线、异步工厂脚手架、UI 增强、事件层、GeckoLib 渲染） | ✅ 是（基座注册其方块，`RegistryBlocks.java:219-241`） |
| `kport.modularmagic` | 139 | ModularMagic（10 种魔法需求、20 个 IO 方块、49 个 JEI 文件） | ✅ 是（基座注册其方块，`RegistryBlocks.java:243-305`） |
| `com.cleanroommc.client` | 22 | Cleanroom 平台工具（`WorldSceneRenderer` 等） | ✅ 是 |

**另有两个「第三方实现、本体接线」的包**，也随发行包发布、且有真实消费者：

| 包 | 是什么 | 本体怎么接线的 |
|---|---|---|
| `ink.ikx.mmce` | **自动搭建整机**（手持物品右键控制器，从背包逐块搭出结构） | `common/data/Config.java:21/71` 加载它的配置；`common/CommonProxy.java:73/155` 注册它的 `AssemblyEventHandler` |
| `youyihj.mmce` | **机器投影仪**（右键控制器 → 世界空间幽灵预览） | `common/registry/RegistryItems.java:47` 注册它的 `MachineProjector` ——**这就是旧发行包里那个能用的 `machine_projector`** |

> 顺带纠正一处常见误解：`hellfirepvp` 包内的 `ItemMachineProjector`（13 行空壳）**从未被注册**，
> 真正注册的是 `youyihj` 那个功能版。新版注释把「13 行惰性物品」当作原版口径，与旧发行包不符。


**所以「本体的 consumer 才第三个算缺口」这条口径不成立。** 正确口径是：
旧版**发出去的那个 jar** 里有这些东西，新版没有——这就要算差异，只是**优先级**可以按「是否属于 MMCE 核心玩法」来分。

本文因此把条目分成两类标注：
- **[核心]**：MMCE 本体作者写的、机器玩法必需；
- **[扩展]**：Kasu / ModularMagic 写进同一个 jar 的能力，可按所有者决定取舍。

## 2. 现状：0.62.9 已经做到什么

### 2.1 机器定义与结构（完成度高，个别字段与一处旋转埋着问题）

- 根字段落地：`registryname` / `localizedname` / `parts` / `failure-action` / `requires-blueprint` /
  `color` / `has-factory` / `factory-only` / `modifiers` / `dynamic-patterns`
  （`machine/MachineSchema.java`）。
- `requires-blueprint` **真的强制**（`MachineRegistry.java:176-186` + 控制器蓝图槽）。
- 四向旋转与旧版同式 `(z,y,-x)`（`MachineRegistry.java:64-91`）；`findMatch` 顺序一致。
- 控制器位置不入结构（`skipOrigin`，并修掉了旧版被注释掉的跳过逻辑）。
- `selector-tag` 全链落地（`HatchCollection.java:208-229`），已实机验收。
- `dynamic-patterns` 解析/量长/合并/段号标签齐（`machine/DynamicPattern.java`）。
- `color`：解析 → 下发 → 客户端 tint **全链实机通过**（0.62.9）。

### 2.2 配方与需求

- 5 种内置需求 + Mekanism 的 `gas` / `gas_pertick`。
- **输出侧**概率 `chance`、数量区间 `minAmount`/`maxAmount` 已实现（比旧版 JSON 能表达的更宽）。
- `perTick` 合并了旧版三种 per-tick 类型（旧版那两个 JSON 入口本来就返回 `null`）。
- 数据包 + 配置目录 + KubeJS 三源加载。

### 2.3 仓口与端口

- 6 族仓口，三条等级阶梯长度与**数值逐项与旧默认值一致**
  （`HatchTier.java:25-33`：物品 1/4/6/9/12/16/32 格；流体 100…32000 mB；
  能量 2048…2,097,152 FE、传输 128…131,072）。
- 并行控制器（4/16/64/256/512）与升级总线槽位（3/6/9/12/18）数值一致。
- 流体与气体互斥（气体优先），Forge 能力齐全。

### 2.4 界面与 JEI

6 个屏（控制器/工厂/仓口/并行/升级总线/蓝图预览）+ JEI 两类（每机器配方 + 结构预览）。
3D 预览带旋转/缩放/平移/图层/循环替换/动态长度 ±。

### 2.5 其他

- 升级总线 + 配方修改器；工厂控制器（独立进度条，非真异步）。
- KubeJS 机器定义（19 个方法）。
- `/mm-diagnose`（新版自有，旧版没有）。
- Jade 仓口流体提示（改用 Jade 原生 fluid-storage API），实机通过。
