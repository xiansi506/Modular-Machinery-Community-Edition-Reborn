## 一、先分清机器、配方和部件

**机器定义**描述每个相对坐标接受什么方块；**机器配方**描述这台机器加工什么；**仓口**提供实际的物品、流体与能源存储。只有结构文件，机器可以成型，却不会自动获得加工配方。

JAR 不自带机器定义和机器加工配方。安装后应能看见部件，但不会凭空出现一套生产线。仓库里的示例数据包需要另外安装。

| 部件 | 用途 |
|---|---|
| 通用机器控制器 `modular_machinery_reborn:machine_controller` | 识别普通机器，打开机器界面；蓝图可指定目标机器 |
| 通用工厂控制器 `modular_machinery_reborn:factory_controller` | 用于允许工厂模式的机器，管理多条配方线程 |
| 物品、流体、能源输入／输出仓 | 收料、供能、接收产物；必须放在定义允许的位置 |
| 并行控制器 | 增加一次执行的配方份数，不会自动加入结构 |
| 升级总线 | 放入已定义升级的物品，为机器提供修改器 |
| 蓝图 | 绑定机器、查看结构、为未成型通用控制器指定搭建目标 |
| 结构构造工具 `itemconstructtool` | 选取现有方块，导出结构片段 |
| 机器投影仪 `machine_projector` | 在世界中显示目标结构的幽灵预览 |

**控制器不是输入箱，也不是能源仓。** 它的蓝图槽不承担配方输入输出；给控制器接管道不能代替给仓口接管道。普通容器也不会仅因在结构里就自动成为机器端口。

JEI 用于查看机器类别、结构和配方；KubeJS 用于脚本定义；Mekanism 提供气体；AE2 提供 ME 相关部件；Jade 提供观察信息；GeckoLib 提供自定义模型动画。这些集成按需选装，不写脚本也能用 JSON 创建机器。

## 二、最小练习：圆石加工机

目标：消耗 **1 圆石**，以 **20 FE/t** 运行 **100 tick**，产出 **1 石头**。100 tick 在正常 20 TPS 下约 5 秒，总计 2000 FE。先用创造模式完成练习，并准备能提供 FE 的电源／模组；如果只装了本框架，可先从配方删掉 energy 需求验证物品流程，再加供电。

完整文件在 [examples/docs-quickstart](../examples/docs-quickstart/README.md)。安装其中的 `datapack` 文件夹，或者按下文手工创建；不要同时安装等价的 KubeJS 示例。

### 1. 创建数据包

单人存档放在 `<实例>/saves/<世界>/datapacks/mm_quickstart/`；专用服务器放在 `<世界>/datapacks/mm_quickstart/`。

```text
mm_quickstart/
├── pack.mcmeta
└── data/tutorial/
    ├── machinery/stone_processor.json
    └── recipes/stone.json
```

`pack.mcmeta`：

```json
{
  "pack": {
    "pack_format": 15,
    "description": "Reborn quickstart: stone processor"
  }
}
```

`data/tutorial/machinery/stone_processor.json`：

```json
{
  "registryname": "tutorial:stone_processor",
  "localizedname": "圆石加工机",
  "requires-blueprint": false,
  "parallelizable": true,
  "max-parallelism": 64,
  "internal-parallelism": 1,
  "parts": [
    { "x": -1, "y": 0, "z": 0, "elements": "modular_machinery_reborn:item_input_hatch" },
    { "x": 1, "y": 0, "z": 0, "elements": "modular_machinery_reborn:item_output_hatch" },
    { "x": 0, "y": -1, "z": 0, "elements": "modular_machinery_reborn:energy_input_hatch" }
  ]
}
```

机器 ID 是 `registryname` 的值 **`tutorial:stone_processor`**，不是文件名，也不由数据包目录自动决定。裸名 `stone_processor` 会补成 `modular_machinery_reborn:stone_processor`，因此建议始终写完整 ID。

坐标以控制器为原点，按**控制器朝北**的结构描述。`x` 正为东、`y` 正为上、`z` 正为南；控制器自身不写进 `parts`。旋转控制器会同时旋转结构位置和有方向的方块状态。

### 2. 添加配方

`data/tutorial/recipes/stone.json`：

```json
{
  "type": "modular_machinery_reborn:machine",
  "machine": "tutorial:stone_processor",
  "registryName": "stone",
  "recipeTime": 100,
  "max-parallelism": 64,
  "requirements": [
    { "type": "item", "io-type": "input", "item": "minecraft:cobblestone", "amount": 1 },
    { "type": "energy", "io-type": "input", "energyPerTick": 20 },
    { "type": "item", "io-type": "output", "item": "minecraft:stone", "amount": 1 }
  ]
}
```

配方资源 ID 由目录得到 **`tutorial:stone`**；`registryName` 是配方对象的名称字段，不负责重命名资源文件。机器文件是小写 `registryname`，配方字段是驼峰 `registryName`，两者不要混淆。

### 3. 加载和搭建

1. 保存 UTF-8 文件，进世界执行 `/reload`，用 `/datapack list enabled` 确认数据包启用；执行 `/mm-syntax` 并检查 `logs/latest.log` 是否有加载错误。
2. 放置通用机器控制器，使其朝北。以控制器为中心，**西侧放物品输入仓、东侧放物品输出仓、正下方放能源输入仓**。这个最小例子不要求额外机箱。
3. 右键控制器，确认结构已识别为“圆石加工机”。朝向不同则按结构预览旋转搭建。
4. 给物品输入仓放入圆石，输出仓留空；把 FE 电源接到能源输入仓，确保既有足够存量也有足够传输速率。练习期间不要给控制器通红石信号。
5. 预期每份圆石加工 100 tick，产出 1 石头。若暂停或不开工，先看界面，再对准控制器执行 `/mm-diagnose`。

可用 `/mm-get_blueprint tutorial:stone_processor` 获取绑定蓝图（命令需权限 2），右键使用蓝图查看结构。当前例子不强制蓝图；若改为 `"requires-blueprint": true`，则把对应蓝图放进控制器。

## 三、三种机器来源，以及什么时候需要重启

三种来源共用机器定义规则；同一逻辑机器 ID 冲突时，**KubeJS 优先于配置目录，配置目录优先于数据包**。同一来源里也应避免重复 ID，建议每台机器只保留一份主定义。

| 来源 | 位置 | 数据修改 | 专属控制器 |
|---|---|---|---|
| 数据包 | `data/<namespace>/machinery/*.json` | `/reload` | 另在配置目录预先声明，重启注册 |
| 配置目录 | `config/modular_machinery_reborn/machinery/*.json` | 结构数据可 `/reload` | 启动时扫描，新增控制器需重启 |
| KubeJS | `kubejs/server_scripts/*.js` | `/reload` | 脚本本身不能在重载时新增方块；可用预声明 |

手写配方放数据包 `data/<namespace>/recipes/`；机器配置目录不是普通配方目录。脚本配方则放 `kubejs/server_scripts/`。不要把 1.12.2 的 `scripts/*.zs` 直接放进来。

数据包／脚本机器可以继续用通用控制器。若需要专属控制器，在配置目录增加一份**仅声明控制器**的文件，例如 `stone_processor_claim.json`：

```json
{
  "registryname": "tutorial:stone_processor",
  "has-factory": false
}
```

不写 `parts`，让完整结构继续由数据包或脚本提供；**重启客户端和服务端**后才有新方块。不要仅为了修改结构重新注册控制器；已发出的控制器物品也不会因删了定义而自动变成别的机器。

`has-factory`、`factory-only` 涉及启动时的控制器集合：新增或改变相应专属控制器应重启，不能指望仅 `/reload` 改变已冻结的方块注册表。

### KubeJS 等价定义

以下是第二节结构的另一种写法，与数据包定义**二选一**。必须调用末尾的 `.register()`：

```js
MachineRegistryEvents.registry(event => {
  event.machine('tutorial:stone_processor')
    .localizedName('圆石加工机')
    .requiresBlueprint(false)
    .parallelizable(true)
    .maxParallelism(64)
    .internalParallelism(1)
    .part(-1, 0, 0, 'modular_machinery_reborn:item_input_hatch')
    .part(1, 0, 0, 'modular_machinery_reborn:item_output_hatch')
    .part(0, -1, 0, 'modular_machinery_reborn:energy_input_hatch')
    .register()
})
```

`.part(x, y, z, ...elements)` 表示一个位置；`.parts(xs, ys, zs, ...elements)` 把三个坐标列表做组合。不要把坐标数组传给 `.part`。配方脚本和完整方法表见 [配方指南](KJS-配方指南.md)。

## 四、从现有建筑导出结构

先在世界中搭出结构，再使用结构构造工具导出坐标。**结构构造工具逐块选择，不是选两个角点的区域棒**。

1. 使用创造模式，并确保有命令权限 2。
2. 放置控制器和周围部件；手持结构构造工具，逐个右键选中控制器以外的方块。选中方块有轮廓，再次右键可取消。
3. 最后右键控制器结束导出，工具按控制器朝向把坐标归一化；选区随之清除。
4. 查看提示的配置目录文件。专用服务器写入的是**服务器的配置目录**，聊天只提示保存信息，不会把整份 JSON 自动下载到客户端；请向服务器管理员取得文件。
5. 导出文件只有 `parts` 片段，不是一份完成的机器。加上 `registryname`、`localizedname` 等字段，或把 `parts` 复制到已有定义。原始片段不要一直留在自动加载目录里，否则缺少名称会产生加载错误。
6. 检查导出的状态和 NBT：不需要强制朝向或等级时，移除对应状态限制。0.111.0 起结构侧 `nbt` 参与匹配，脚本还可以附加方块检查器；库存、能量等动态 NBT 可能使机器随内容变化而失去成型状态，应只保留确实需要的条件。0.112.0 起 `preview-nbt` 在蓝图／JEI 中创建并渲染独立方块实体；显示数据的字符串按字面读取，普通 JSON 数字／布尔可直接写。参见 [预览 NBT 示例](../examples/preview-nbt/README.md)。结构与物品配方的 NBT 模板都按各自上下文读取。

`elements` 写方块 ID 时接受其任意合法状态；写 `minecraft:oak_log[axis=y]` 就要求轴向；数组表示同一位置的备选项，不是同时需要全部方块。结构材料不能直接照抄配方的 `#物品标签` 写法，需要具体方块描述符或变量集。坐标列表写法见配方指南的机器字段部分。

需要复用材料候选时，在 `data/tutorial/machinery/materials.var.json` 写变量集：

```json
{
  "frame": ["minecraft:iron_block", "minecraft:gold_block"]
}
```

随后在某个部件里使用 `"elements": "frame"`，表示这个位置接受铁块或金块。变量名没有命名空间，材料描述符应写完整方块 ID；变量值也可为单个描述符字符串。建议变量使用不冲突的名称。

## 五、蓝图、投影与自动搭建

**蓝图结构预览**：右键使用绑定蓝图打开结构视图，可旋转观察、切换图层。装有 JEI 时还可查看机器结构类别；预览材料格支持 JEI 配方／用途操作，按键以 JEI 配置为准。

**世界投影**：先让控制器知道目标机器。专属控制器已有绑定；未成型的通用控制器可先放对应蓝图。手持机器投影仪右键控制器开关幽灵预览，再次对同一控制器使用可取消；走远、断线或整机搭建完成也会清除。投影只显示提示，不会消耗或放置方块。

**自动搭建**：在相同的目标绑定基础上，携带所需材料，主手拿触发物品（默认木棍），**不潜行**右键控制器。任务逐步放置缺失部件；受占位、可放置条件、事件保护和材料限制。动态段未成型时使用最小规模。触发物品与速度可在配置调整；已有障碍不应当当作材料不足反复触发。

结构构造工具负责“导出已有结构”，投影仪负责“显示目标”，自动搭建负责“从物品栏放部件”，三者入口不同。

## 六、并行与工厂

**并行**是在一次合成里结算 N 份。机器的 `parallelizable`、`max-parallelism`、`internal-parallelism` 与结构里的并行控制器共同提供额度；配方还可用 `max-parallelism` 限制。最终值受当前输入、能源和输出空间约束，不能只看面板最大值。

第二节只有内置并行 1；想增加并行，可把内置值改成 4，或者在 `parts` 新增允许并行控制器的位置后按预览搭建。并行控制器五档默认最大值为 4／16／64／256／512，可在其界面调整当前贡献；单纯把方块贴在机器旁边无效。

**工厂**让不同配方在独立进度条中同时运行，每条配方仍可有自己的并行。完整定义设置 `has-factory: true`、`max-threads` 等，再使用工厂控制器。脚本可用 `.hasFactory(true).maxThreads(2)`；需要新专属工厂控制器时按第三节预声明并重启。

多个线程共享机器端口和并行额度；并行不是“线程数”，工厂也不是真正的异步线程池。新开工及重开工都会按当前资源重新计算，不能依赖上一批留下的并行值或催化剂增益。

0.115.0 起，Jade 会合计核心线程与普通线程的能量消耗／生成。显示的是当前配方需求速率，临时阻塞但仍持有配方的线程也计入；详见 [工厂能量信息](工厂能量信息.md)。

## 七、进阶结构、模型和集成

| 目标 | 配置入口和注意点 |
|---|---|
| 染色 | 机器根字段 `color`，例如 `"55AADD"`；作用表现与具体部件有关 |
| 按结构部件加速／增产 | 根字段 `modifiers` 或 `multi-block-modifiers`；修改器计算见配方指南 |
| 可变长度结构 | 根字段 `dynamic-patterns`，声明重复段、方向、最小／最大次数及可选末端；先保证固定结构正确再扩展 |
| 数值模式 | 根字段 `smart-interfaces`，在控制器里设置数值，配方用 `interface_number_input` 匹配；没有独立智能接口方块 |
| 限定需求访问端口 | 结构部件 `selector-tag`，配方需求同名字段；不要与物品／方块标签混淆 |
| GeckoLib 模型 | 根字段 `geo-model`；需要安装 GeckoLib，资源放资源包而不是服务端数据目录 |
| ME 自动化 | 需要 AE2 及有效频道与网络供电；加工样板供应器把原料存入内部缓冲，由匹配结构中的供应器或影子方块向机器提供输入。气体通道另需 Mekanism 和 Applied Mekanistics |

动态段的每项使用 `name`、`faces`、`minSize`（默认 0）、`maxSize` 和 `parts`，可附 `parts-end`。`structure-size-offset-start` 指定起点，`structure-size-offset` 指定重复步长，均为 `{ "x": ..., "y": ..., "z": ... }`；不要省略步长后期待自动沿方向拉长。重复范围、末端与固定结构要避免冲突，投影／搭建未成型结构时以最小规模为起点。

模型例子是机器根对象的**片段**，合并进完整定义：

```json
{
  "geo-model": {
    "model": "tutorial:geo/processor.geo.json",
    "texture": "tutorial:textures/block/processor.png",
    "animation": "tutorial:animations/processor.animation.json",
    "idle": "animation.processor.idle",
    "working": "animation.processor.working"
  }
}
```

资源包路径分别为 `assets/tutorial/geo/processor.geo.json`、`assets/tutorial/textures/block/processor.png`、`assets/tutorial/animations/processor.animation.json`。动画名必须与导出文件一致。不使用动画可省略后三项；模型和纹理必须存在。建议显式使用自有命名空间，确保资源路径明确。

### ME 气体传输与加工样板（0.109.0）

安装 **AE2 15.x、Mekanism 10.4.x、Applied Mekanistics 1.4.3** 后，现有 ME 输入／输出总线同时提供气体功能，不增加新的气体总线方块。每个总线有独立的 9×8000 mB 气体池，与其流体池分开存储；普通流体仓原有的气液互斥规则继续保留。

- **从网络供气**：把 ME 输入总线纳入结构并连接有频道、供电正常的 ME 网络。在输入总线配置格上，拿装有气体的化学品储罐右键，标记容器内气体；也可使用气体的 AE 编码标记。物品／流体／气体标记在同一格互斥，标记操作不消耗手中物品。总线按目标量从网络补气，超量或清除标记后送回；重复气体标记合并目标，最多维持全池容量 72000 mB。
- **把产气送回网络**：结构中放 ME 输出总线，配方使用 `gas` 或 `gas_pertick` 的输出需求。产出的气体进入其气体池，再送到 ME 网络；网络收不下时保留在总线里。
- **加工样板推气**：用 Applied Mekanistics 支持的气体成分编码加工样板，放入样板供应器。供应器把物品、流体、气体整批存入自身缓冲；遇到不支持的成分或数量溢出时整批拒绝。机器通过供应器或已绑定的影子方块读取缓冲。样板目标与机器加工配方仍须匹配，产物通过相应输出端口回网。

气体配置与库存随存档和客户端镜像同步；气体以颜色条和名称／数量提示显示。没有 Applied Mekanistics 时气体不会自动进出 ME 网络，气体标记悬停会提示依赖；普通 Mekanism 气体需求无需该附属。本轮未在真实 AE2 网络或游戏界面中验收，先在测试世界验证供气、产气回网、样板混合推料及重登恢复。

当前 0.111.0 通信协议为 **5**，客户端与服务端必须一起更新。

## 八、排错和升级

以下诊断命令需要相应权限；命令检查成功也不等于真实管道、世界交互和第三方网络已经通过验收。

| 症状 | 首先检查 |
|---|---|
| 没有机器／蓝图 | `/datapack list enabled`、`/mm-syntax`；查日志 `Failed to load machine definition`，核对 `registryname` 和脚本 `.register()` |
| 有机器但没有专属控制器 | 是否创建了配置目录声明，是否在客户端和服务端一起重启；`/reload` 不新增方块 |
| 结构不成型 | 蓝图是否必需、控制器朝向、相对坐标、仓口家族、方块状态、结构 NBT 与脚本方块条件；先看蓝图预览，再检查服务端脚本日志 |
| 成型但没有配方 | 文件在 `recipes/` 而不是 `machinery/`；根 `type`、完整 `machine` ID、脚本错误和重复配方 ID |
| 有配方但不开工 | `/mm-diagnose`，检查仓口、输入、能源、输出空间、红石信号、数值模式和分组／选择标签 |
| 能量足够却频繁暂停 | 供电速率是否满足“每 tick 能耗 × 并行”，端口是否确实属于结构 |
| 气体报未知需求或不进仓 | 是否安装 Mekanism；用完整气体 ID；有流体时先排空，气液不能同时正常注入同仓 |
| 连续合成或联机异常 | 两端是否同版本，重登后定义是否同步；提供日志、最小结构／配方与复现步骤 |

升级前备份存档、数据包和脚本；客户端和服务端同时更新，`mods` 中只保留一份本模组。从 0.107.0 旧适配器配方迁移前先完成在途合成，旧工厂缺失的存档字段无法事后还原；运行中更改或删除配方也不保证按旧定义完整续跑。

接下来阅读 [配方指南](KJS-配方指南.md)；真实联机、AE2、气体管道、投影与自动搭建的验证边界见 [已知限制](已知限制.md)，版本变更见 [迁移日志](../迁移日志.md)。

### ME机械样板供应器与 ME机械样板镜像（0.111.0）

这两个方块的显示名为 **ME机械样板供应器（ME Machinery Pattern Provider）**和 **ME机械样板镜像（ME Machinery Pattern Mirror Image）**。注册 ID 仍为 `modular_machinery_reborn:me_pattern_provider` 与 `modular_machinery_reborn:me_pattern_mirror`，存档中的方块身份不变。下文“供应器”和“镜像”分别指这两个部件。

供应器有 **36 个真实编码样板槽**。在 AE2 样板终端中编码加工样板后放入；仅加工样板参与 ME 合成广播。供应器要接入有电力和频道的 ME 网络，物品管道也可通过物品能力放入／取出编码样板。

供应器先把整批原料存入自己的持久缓冲，机器再从缓冲取料。因此收料不要求机器已经成型，也不受普通输入仓的容量限制。要让机器实际加工，结构定义必须接纳 `modular_machinery_reborn:me_pattern_provider`，供应器必须是匹配结构中的部件；仅仅放在机器旁边不会供料。离线时不接收新任务，但已保存的材料仍可供已加载机器使用。加工产物仍需经输出仓／ME 输出总线回网。

右上角按钮循环切换五种模式：

| 模式 | 行为 |
|---|---|
| 默认 | 不设批次门控，多种样板共用缓冲 |
| 合成锁 | 接收一批后锁住，直到使用该供应器或其影子方块的机器发出配方完成事件；中途取消可用退回按钮解除锁 |
| 强化阻挡 | 样板缓冲非空时只接收当前样板；材料被取空后可以接收其他样板，不等待加工完成 |
| 阻挡 | 样板缓冲为空才接收下一批；手动输入不参与阻挡 |
| 隔离输入 | 每个样板槽有独立缓冲和自动分配的输入组，不能把两个样板槽的原料拼成一份配方 |

进入或离开隔离模式会先退回样板缓冲，再完成切换。退回使用 ME 网络电力，网络离线、缺电或存储不足时保留余量并自动重试；等待期间拒绝新批次。更换一个有缓存的隔离样板槽时，只退回该槽的旧原料，避免旧任务与新样板串料。退回原料不会替你取消 ME 合成 CPU 中的任务。

右侧有两个**手动物品槽**和一个手动流体罐。流体容器拿到菜单鼠标光标上后点“流体容器”按钮，可倒入／取出；空容器或填充结果必须有空间存放。手动输入在隔离模式中对所有样板组共用，退回按钮和模式切换都保留它们，适合放辅助原料或催化剂。手动流体不接收气体。非隔离模式的“输入组”可设为 `-1`（通用）或 `0..65535`，点旁边的勾应用；隔离模式的子槽组由系统分配。

“查看缓冲”在样板格区域显示材料名称、数量和样板槽号；星号表示共用缓冲。鼠标滚轮浏览当前页，用右侧 `<` / `>` 翻页。每次同步最多 32 行，实际存储不会因此截断。破坏供应器后的正常掉落携带样板、手动输入、缓冲和等待退回状态，重新放置后恢复。

**影子方块** `modular_machinery_reborn:me_pattern_mirror` 可让其他结构读取同一供应器，自己不复制材料，也不提供第二套样板槽：

1. 手持 AE2 存储卡，潜行右击供应器，记录其位置。
2. 在同一维度中，用这张卡普通右击影子方块完成绑定。
3. 让结构定义接纳影子方块，并将它放在匹配结构的部件位置。

供应器所在区块必须已经加载；影子方块不会强制加载远处区块，也不跨维度供料。多个入口在同一次结算中共用同一份资源事务，不能重复计数。普通物品／流体只需 AE2；缓冲中的气体还需 Mekanism 和 Applied Mekanistics 1.4.3。

升级前先完成旧版本正在运行的供应器任务；已有三种模式的存档编号保留，但旧版本已直接送入机器仓口的材料不会自动搬回新缓冲。**通信协议为 5，客户端和服务端必须同时更新。** 以上机制已有离线检查，真实 ME 合成 CPU、频道／电力、界面、区块生命周期、重登及拆放仍需统一实机验收。

### 界面操作细节（0.110.0）

供应器模式按钮支持左键切换下一项、右键切换上一项，并在提示中标出当前模式及等待切换的目标。右下方显示网络在线／离线、合成锁或退回中；退回还需要网络电力与存储空间。

输入组填写 -1（通用）或 0–65535，点击“确定”或按 Enter 应用，Esc 放弃本次编辑，Tab 切换焦点。非法值会变色，确认按钮按状态禁用；提示显示服务端当前值。隔离模式由系统自动分组，输入框不可编辑。

“查看缓冲”每次显示四行，滚轮或拖动右侧滚动条浏览本页，箭头切换服务器返回的页面。名称、图标和数量分列，名称过长会省略；悬停查看来源样板槽、类型及精确数量。k/M/G/T/P/E 是数量缩写，流体和气体的精确数量使用 mB。超大物品数据会使用基础图标，极长自定义文案会截短，实际库存保持完整。

手动流体显示在右侧第三格，悬停可看名称与容量。把流体容器拿到鼠标光标上，按钮会在可操作时启用；服务端以操作栏文字报告转移结果。ME 总线的流体使用原生贴图及颜色，精确数量仍见悬停。

蓝图和 JEI 结构预览上方显示可见／总方块数；底部最右侧菜单可折叠按钮，当前切层、循环和信息状态会保留。长标题和信息可通过悬停查看。开启 F3 后可查看最近预览的实际方块数和客户端绘制调用耗时，旧数据会标明，断线清空。

这些界面行为已有离线检查及布局核对，真实游戏中的 GUI 缩放、字体、纹理、键盘焦点、F3 和网络交互仍待实机验收。
