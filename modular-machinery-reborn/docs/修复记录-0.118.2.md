# JEI 多方块预览修复（0.118.2）

本轮处理预览排查中的七项问题，保留此前 0.118.1 的配方、AE2、刷新和缓存修复。网络格式未变，协议仍为 **7**，没有新增集成。

1. **相机与光照空间**：1.20.1 的 `PoseStack.mulPoseMatrix` 不更新法线。相机变换现在同时更新顶点矩阵和法线矩阵，光照沿相同视图旋转。
2. **成型控制器**：临时控制器加载预览 NBT 后，再强制绑定当前机器 ID、成型标志和空闲状态，移除活动配方字段。场景缓存包含机器 ID 和成型状态，切换后不会复用旧实体；预览世界仍不执行 tick。
3. **动态材料**：JEI 真实槽位使用当前面板的材料种类和数量。更新显示覆盖时先替换旧列表，避免长度反复增减后积累旧数量。同一机器的不同 JEI 历史布局按各自真实槽位更新，避免覆盖另一页。隐藏搜索索引包含可替换材料以及初始长度为零的动态段，不展开最大长度。
4. **流体**：普通方块之外增加液体绘制，支持水、岩浆和含水方块。液体原生的区段坐标转换为当前方块坐标，再应用相机位置和法线变换；使用方块图集和 GUI 主目标的透明渲染类型。
5. **拾取视口**：移除较小拟合正方形的提前排除，由面板真实视口限制鼠标输入。射线继续使用相同透视相机和可见方块集合。
6. **物品交互**：选中方块及最多六个候选图标成为真实 JEI 槽位，交给 JEI 的提示、点击和配方／用途查询处理。面板不吞掉这些槽位的按下事件；在图标上松开之前从视口开始的拖动，也会正确结束。
7. **异常清理**：预览独立于共享 GUI 顶点缓冲。失败批次仅结束并释放 CPU 数据，不补绘残留顶点；原版 `discard()` 不退出构建状态，因此不能单独作为恢复手段。无法结束的缓冲不再复用。视口及标题裁剪使用 `finally`，矩阵恢复也有嵌套清理。失败模型按场景隔离，避免每帧重复触发同一异常。

专项通过真实 JOML/PoseStack、控制器实体的加载、JEI 15 `RecipeSlot` 的显示覆盖和命中框、原生 CPU `BufferBuilder` 中断恢复，以及水／岩浆／含水状态的液体调度分支检查行为。JEI runtime 服务和液体调度器在相应检查中使用测试替身；没有实际绘制纹理、打开物品提示或运行 Forge 客户端。完整计数、构建结果与包哈希以 [交接](交接-2026-10-23.md) §零及归档说明为准。

初次测试暴露了缓冲 `discard()` 的状态差异，已补结束／释放及失败弃用处理；测试脚本还纠正了返回类型断言、切片夹取假设及缺少原生库／FML language JAR 的运行环境。初次失败日志保留，最终成功记录单列，不把旧缺陷复现器作为修复后验收结果。

尚未进行真实 OpenGL／Forge 游戏验收，尤其是流体透明混合、第三方方块模型、成型 GeckoLib 动画和不同 GUI 缩放。未部署、暂存、提交、推送或上传 GitHub。

## English

This patch addresses all seven findings in the JEI multiblock preview review. Camera normals now follow the view transform; temporary controllers receive machine identity and formed state; native JEI slots track dynamic material counts and selected alternatives; fluids have a dedicated transformed rendering pass; picking covers the actual viewport; selected icons defer ingredient interaction to JEI; and private buffers, scissor scopes and matrix cleanup contain rendering failures.

The previous 0.118.1 recipe, AE2, dependency-refresh and reflection-cache fixes remain included. Protocol **7** and the authorized integration scope are unchanged.

Offline checks exercise real geometry, controller loading, JEI slot display overrides/hit rectangles and native CPU buffer recovery. Runtime services and the liquid dispatcher use fixtures where needed. No OpenGL rendering, tooltip display or Forge gameplay acceptance was performed. See the handoff and archive notes for exact results and SHA-256. The game instance was not changed, and nothing was staged, committed, pushed or published.
