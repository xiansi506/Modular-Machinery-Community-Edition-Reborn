# 0.107.3 修复记录 · 2026-10-25

**已完成：修复上轮确认的四类缺陷，构建并归档 0.107.3。未进游戏、未部署。** 原审查的六个缺陷复现场景保留在 `../recheck-0.107.2/`，不能把其中 CONFIRMED 计作产品通过。

## 修复范围与旧版依据

1. **工厂并行分配**：对照 1.12.2 `RecipeCraftingContext.canStartCrafting` 和 `RecipeThread`，新开工、连续重开工统一重新计算当前组资源、输出空间、配方上限与机器剩余额度。机器上限 64、只有 1 煤时可按 1 并行开工；配方上限 1 时不能按 64 扣料。使用执行副本，不污染注册配方。
2. **催化剂支付与增益绑定**：对照旧版 `RequirementCatalyst` 检查后记录必付状态的机制，引入不可变 `MachineRecipe.StartPlan`，把选中的催化剂、有效修改器、并行数与可行性绑定。普通输入和选中催化剂在同一事务视图上预留，按定义顺序为可支付的催化剂分配资源；开工复核并严格支付选中项，库存失效时拒绝整次开工，不能跳过支付而保留增益。计算包含机器基础修改器，也支持催化剂降低输入使配方可行；完成后的重开工从基础修改器重新计算，不叠加上一批增益。消耗概率仍按旧语义：概率 0 可以不消耗，但选择时必须有对应材料；概率 1 必须支付。
3. **单机宿主同步隔离**：服务端权威定义、旋转缓存和同步源 JSON 保留原注册表；客户端收到的数据写入独立 `ClientView`。JEI、渲染、蓝图、物品名称、形状和控制器查询按世界或逻辑线程选择相应视图。空客户端同步不回退读取宿主服务端定义，客户端同步和清理不破坏下一次登录要发送的源 JSON。
4. **访客退出不清空宿主定义**：清理入口从通用玩家退出事件改为真实客户端网络断开事件 `ClientPlayerNetworkEvent.LoggingOut`。通用服务端玩家退出事件不会匹配该回调；断开只清客户端视图。另为现有 12 类网络消息声明各自 PLAY_TO_CLIENT / PLAY_TO_SERVER 方向，数据格式不变，协议仍为 2。

旧源码位于项目同级 `_mmce-src/ModularMachinery-Community-Edition-master/src/main/java/`，具体旧版位置和原始复现结果见上轮复查报告。生产代码涉及 16 个 Java 文件，清单为 `changed-source-files.txt`；修复前源文件和验证器在 `before/`，差异为 `source-changes.patch` 与 `harness-changes.patch`。
