# 0.108.0 · ME 气体功能更新 · 2026-10-25

完成统一 ME 总线的气体输入／输出和气体加工样板，版本由 0.107.3 升到 **0.108.0**。代码基线为本地 HEAD `36f34b0`；本轮未提交、未推送、未部署，也未启动游戏。

## 对接依据与范围

实例中已有 `Applied-Mekanistics-1.4.3.jar`，已核对它与官方 Modrinth 1.4.3 文件的 SHA-512 一致（版本信息 `appmek-version.json`）。通过真实 JAR 的 `MekanismKey` / `getForm()` / `getStack()` / `of()` 核对接口，并使用官方 Maven 坐标 `maven.modrinth:IiATswDj:9n9p68Qq`；本地依赖分支使用同版本 JAR，不把第三方二进制入库。[官方版本页](https://modrinth.com/mod/applied-mekanistics/version/1.4.3)。

旧 1.12.2 `MEGasBus` 的气体池为 9×8000，本版沿用这个基础容量，但按此前统一总线决定并入 `me_item_input_bus` / `me_item_output_bus`；不会新增三套总线方块。当前 ME 供气按目标量，与既有物品／流体接口模型一致。

本轮支持 **Mekanism Gas**。灌注物、颜料、浆液不会被错误地当成气体接收。普通阻挡／隔离输入、旧供应器内部无限子槽等不是本轮范围；JEI 气体格仍保留既有文本显示。

## 实现

- `MeGasStorage` 只使用公共类型；`MeGasTanks` 在 Mekanism 兼容层实现真实 `IGasHandler`。主模块不新增对 Mekanism 或 AppMek API 的直接类型依赖。
- 每台统一总线新增独立气体池，9 罐、每罐 8000 mB；流体池不被覆盖。气体插入优先补同种罐，支持跨罐，模拟无副作用。
- 输入总线配置格支持气体标记，与物品／流体互斥。可用装气体的化学品储罐右键，或使用气体的 AE 编码标记；目标量夹到 72000 mB。同气体多格合并目标，全部 16 格都有效；清除或改类型后多余库存回网，先回送再补新的类型。抽气前模拟余量，满池不抽，网络只接收部分时保留余量。
- 输出总线把产气池中的气体送回网络。桥接每次读取当前 Grid，要求节点在线／激活，使用 AE2 `StorageHelper.poweredInsert` / `poweredExtraction` 与机器动作来源，不绕过网络供电与权限路径。
- `MekanismAnchor` 把统一总线的同一个气体处理器暴露给能力查询和配方端口收集；组号和 selector 保持原收集规则。
- 样板额外成分处理器只在 AE2、Mekanism、AppMek 全部在场时注册。真实 `MekanismKey` 气体成分与物品／流体共用一个 `ResourceTransaction`，只提交一次；缺空间、非法数量、未知成分和后续执行拒绝都不能留下半批输入。
- 气体池实现 `OpaquePort`：虚拟状态独立预留、提交前检查未被外部修改、后续提交失败恢复原内容。普通混合流体仓既有气液互斥事务未改变。
- 库存和标记进入 NBT / update tag；镜像载入先清旧内容，避免空快照残留标记。没有 Mekanism 时保留原始 `meGas` 数据，避免仅因缺依赖覆盖存档。
- 输入界面显示气体标记与目标量，输入／输出气体池有独立颜色条和名称／数量提示。没有 AppMek 的气体标记提示所需依赖；与流体条分区，避免重叠。增加两条中英文语言键，各 **333** 键。
- 配置包增加 GAS 模式并校验枚举、当前菜单、距离、维度、槽号与气体 ID。通信协议从 2 升到 **3**，旧客户端在通道握手时拒绝，不进入旧枚举解码。
