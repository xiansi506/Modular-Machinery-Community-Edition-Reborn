# 0.107.2 · 气液互斥与结构状态旋转

本轮只处理用户指定的两项问题，保留既有未提交改动。版本从 0.107.1 升至 0.107.2。已构建和完成离线回归，未启动游戏、未替换实例 jar、未提交或推送 Git。

## 气体注入不再清除已有流体

1.12.2 的 `hellfirepvp/modularmachinery/common/util/HybridGasTank.java` 中，`receiveGas` 在已有流体时明确返回 0。此前代码注释把直接赋值 `setGas` 的内容置换语义误套到传输上，导致 EXECUTE 注气清掉原流体；本轮纠正实现和注释。

- `HybridGasTank.insertChemicalInternal` 在真实流体量大于零时整份拒绝，SIMULATE 和 EXECUTE 都不修改内容。排空后可切换介质，空仓正常接收、容量和气体类型检查保留。
- 删除仓口的 `clearFluidForGas/clearForGas` 传输清空入口，改为提供真实流体副本供事务验证和恢复。
- 气体与流体的事务视图共用占用状态：先预留气体就拒绝再填流体，反之亦然；同一批次先排空再切换介质则可执行。不能只检查真实罐的初始状态，否则模拟会给两种介质同时承诺同一仓位。
- 事务校验包含真实流体副本，执行失败可恢复两种资源；没有变化的流体存储跳过重复恢复，避免把旧异常存档里被气体显示闸门隐藏的内容清掉。
- 底层直接赋值 setter 仍用于装载/恢复内容；它不等同于管道的插入请求。本轮修复针对正常传输和配方结算。

## 结构旋转同步旋转方块状态

旧版 `BlockArray.rotateYCCW` 调用 `BlockInformation.copyRotateYCCW`，后者通过 `IBlockStateDescriptor.copyRotateYCCW` 对可接受状态逐一调用 `withRotation(COUNTERCLOCKWISE_90)`。本版改为调用对应的 `BlockState.rotate`。

- `MachinePattern` 同时旋转坐标、标签和每个候选的状态条件。
- `BlockMatcher` 旋转其接受的完整状态集合，再归并为等价的部分属性条件，未声明的属性继续保持通配。这样不仅支持 facing 和 axis，也支持栅栏、墙、藤蔓、红石线的方向属性名称交换。
- 自定义方块若将多个属性耦合旋转、结果不能写成一个部分条件，则保留精确候选列表，避免放宽或收紧匹配集合。结果按 matcher 缓存，无属性要求走原通配路径。
- 旋转后的 descriptor 可被现有解析器读回，因此投影仪同步、世界幽灵与自动搭建取得相同的旋转后状态，不需要改网络协议。协议仍为 2。
