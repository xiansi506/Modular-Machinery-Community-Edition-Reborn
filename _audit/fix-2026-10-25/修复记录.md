### 默认 Maven 构建

默认依赖声明已补齐并实际编译通过；最终 jar 来自默认 Maven 分支的打包。这不是从空缓存开始的全量下载测试：Forge 基础缓存已存在，部分第三方原件复用与官方校验值完全相同的本地文件；Rhino 和 Architectury 另取官方原件后校验。`maven-integrity.json`、`maven-verified-cache.txt` 保留校验依据，Gradle 日志也记录了 matching checksum。Rhino 本地包与官方包仅 manifest 不同、所有 class 内容相同，见 `rhino-packaging-comparison.txt`。

本机 ForgeGradle 的额外服务器连接预检会在 SSL 握手等待，连 `--offline` 也会触发。成功验证命令临时传入 `-Dnet.minecraftforge.gradle.check.certs=false`，只跳过该额外预检，没有修改项目配置或依赖下载的 HTTPS 验证。首次失败和手动停止的尝试保留在 `maven-*.log`；其后正式成功证据为 `maven-compile-final.log` 和 `build-release.log`，汇总见 `maven-status.txt`。

## 升级兼容性与剩余实机清单

1. **两端同时升级**：需求 wire 多了一个布尔字段，协议从 1 升到 2。
2. **升级前完成旧适配器合成**：0.107.0 用流水号生成 ID，旧存档里没有源配方身份，无法可靠自动转换。新 ID 稳定，但这不保证正在运行的旧 ID 可以续跑。不要靠猜测把旧在途合成绑定到另一个配方。
3. **旧存档缺失信息不可恢复**：旧工厂 NBT 没有并行数和冻结修改器，兼容读取只能使用旧数据允许的默认值；本版开始保存完整状态。新版本存档降级到旧版会丢这些状态。
4. **reload 修改正在合成的定义**：只改变其他配方或枚举顺序不会改 ID；若直接修改/删除同一活动配方，其内容仍按现有注册表解析，不保证旧定义完整续跑。调整活动配方前先完成合成。
5. **第三方端口契约**：内建 ItemStackHandler/FluidTank/MeFluidTanks/EnergyStorage/HybridGasTank 有直接恢复路径。任意外部 handler 若 SIMULATE 与 EXECUTE 行为矛盾、拒绝反向操作，无法普遍保证回滚；新不透明端口需实现 `ResourceTransaction.OpaquePort`。本轮不改写现有混合流体/气体罐的互斥覆盖设计。
6. **最小实机复验**：真实 AE2 CPU 混合物品/流体样板（空间不足不丢不复制、足够后整批到账）；相邻两机器不串料；供应器第 10 格重登与破坏重放、两种锁重载后完成解锁；32 并行工厂运行中存档重登；生存自动搭建使用第二候选、已有部分、满桶和保护事件取消；通用/专属未成型控制器投影、负 Y 层和朝向；Mekanism 气体数量/概率修改器的实际结算。

本轮不把原清单中的暂缓功能（旧无限子槽、MekEng、GT/IC2 等集成和其他发布事项）算作已完成，它们没有因这次缺陷修复自动实现。
